# AI 위험 가설 1회 실행 기록 (2026-10-23)

규칙 밖 위험 탐색([`docs/explore.md`](../../explore.md))의 AI 가설 단계를 실제 모델로 한 번 돌린 기록이다.
**사례 1건이지 성능 평가가 아니다.** 같은 조건에서 반복 실행하거나 다른 회사 문서로 일반화한 결과가 아니다.

## 조건

| 항목 | 값 |
|---|---|
| 그래프 | 별빛상점(가상 회사) 데모 v5 — 결제 수정안 4건 승인 후, 해시 `8115e40a1332…` |
| 모델 | `claude-sonnet-5-5`, effort medium, 가설 최대 5개(n=5), 출력 상한 4,000토큰 |

| 판정 | 모든 가설을 결정적 리허설로 재생. 목표 시간은 정책값, 그래프에 없는 전제가 있으면 '확인 필요' |
| 재현 | [`scripts/explore_ai_once.py`](../../../scripts/explore_ai_once.py) (`dry`로 무료 시험 실행 가능) · 원자료 [`2026-10-23-dmc-v5.json`](2026-10-23-dmc-v5.json) · 최소 실패 조건 재검증 [`scripts/explore_ai_minimize.py`](../../../scripts/explore_ai_minimize.py) (사후 재검증, LLM 0회 — 위 유료 실행 기록에는 없음) |

## 결과

- **A. 검증 엔진만:** 고정 규칙이 보고하지 않은 끊김 4건(결제 2 · 주문 2), 모두 리허설로 재현.
- **B. AI 가설:** 제안 5개, 형식 오류 0, 검증 엔진 결과와 중복 0.

| 상태 | 서비스 | AI 가설 | 리허설 |
|---|---|---|---|
| 확인됨 | 추천 | 강현우 부재 + 상품 카탈로그 동시 장애 ("추천은 상품 카탈로그에 의존") | 실패 — 담당 호출이 박재현에서 끊김(상향 경로 없음) |
| 확인 필요 | 광고 | 강현우 · 박재현 연휴 동시 부재 (전제: 함께 휴가를 쓸 수 있다) | 전제가 그래프에 없어 확정하지 않음 |
| 확인 필요 | 웹 프론트엔드 | 전화 + 상암 IDC 동시 장애 (전제: 전화망이 IDC 장애와 무관하다고 보장되지 않음) | 전제가 그래프에 없어 확정하지 않음 |
| 기각 | 이메일 | 이수진 부재 + 클라우드 서울 리전 중단 | 목표 시간 안에 완화(35분) |
| 기각 | 장바구니 | 이수진 부재 + flagd 장애 | 목표 시간 안에 완화(35분) |

- **AI만의 추가 기여:** 검증 엔진이 보고하지 않았고 리허설로 확인된 끊김 1건(추천).
  - 추천은 3등급 서비스라 자동 전수 탐색(핵심 1·2등급만)의 범위 밖이었다. AI가 서비스 의존 관계를 근거로 범위 밖 조합을 제안했고, 검증 엔진이 확인했다.
  - **분리 실험(LLM 0회, [`2026-10-23-dmc-v5-ablation.json`](2026-10-23-dmc-v5-ablation.json), [`scripts/explore_ai_ablation.py`](../../../scripts/explore_ai_ablation.py)):**

    | 조건 | 결과 |
    |---|---|
    | 강현우만 부재 | 통과 (35분 안에 완화) |
    | 상품 카탈로그 동시 장애만 | **실패** — 추천 기능 플래그 OFF 승인이 박재현에서 막힘 |
    | 강현우 부재 + 카탈로그 동시 장애 (AI 가설) | 실패 — 담당 호출이 박재현에서 끊김 |
    | 박재현만 부재 | 실패 — 승인이 박재현에서 막힘 |

  - 따라서 AI가 낸 조합은 **최소 조합이 아니다.** 강현우 부재는 필요 없고, 최소 실패 조건은 "상품 카탈로그 동시 장애 하나"다. 카탈로그 대응에 박재현이 불려 가면, 박재현 한 명에게 몰린 추천의 승인이 막힌다(추천 승인의 단일 장애점). 고정 규칙의 단일 장애점 검사(JT-SPF)는 핵심 서비스만 보므로 이 끊김은 보고되지 않았다.
  - AI가 쓴 설명("강현우의 대응이 갈라지고…")은 검증 대상이 아니다. 리허설이 확인한 것은 주어진 교란 조합에서 경로가 끊긴다는 사실뿐이다.
  - **최소 실패 조건 자동 검증(LLM 0회, [`2026-10-23-dmc-v5-minimize.json`](2026-10-23-dmc-v5-minimize.json), [`scripts/explore_ai_minimize.py`](../../../scripts/explore_ai_minimize.py)):** 위 분리 실험을 이제 검증 단계가 자동으로 한다([`docs/explore.md`](../../explore.md) 5장).
    - 같은 v5 그래프(해시 `8115e40a1332…`, 데모 DB 사본)에서 기록된 AI 가설 5건을 승인 뒤 재판정 경로로 다시 확인했다. 상태·리허설 기록은 5건 모두 기록과 같다(확인됨 1 · 확인 필요 2 · 기각 2, JSON의 `verification_same_as_record`). 자동 전수 탐색 결과 4건도 A(검증 엔진만) 기록과 id·상태·리허설 기록이 그대로다(`sweep_unchanged`).
    - 확인됨인 추천 가설만 대상이다(확인 필요·기각은 대상 아님). 부분 조합 2개를 같은 서비스·같은 목표 시간(1,440분)으로 리허설했다.
    - 결과: **최소 실패 조건 "상품 카탈로그 동시 장애", 불필요한 조건 "강현우 부재"** — 수동 분리 실험과 같다. 끊긴 지점은 같은 박재현이고 단계만 다르다(AI 조합 전체: 담당 호출이 끊김, 카탈로그만: 추천 기능 플래그 OFF 승인이 막힘). 리포트에 이 차이를 함께 적는다.
    - 부분 조합이 원래 가설과 **다른 지점**에서 끊기면 같은 위험의 재현으로 보지 않고 따로 표시한다. 조건을 빼는 근거로도 쓰지 않는다.
    - 이 검증은 AI가 제안한 조건 안에서 필요 없는 조건을 덜어 낼 뿐이다. 박재현만 부재해도 끊긴다는 사실(분리 실험의 마지막 줄)처럼, AI가 제안하지 않은 조건은 찾지 않는다.
- **기각의 뜻:** 위험이 없다는 증명이 아니라, 지금 그래프와 정책 목표 시간에서 실패가 재현되지 않았다는 뜻이다.
- **안전장치가 동작한 것:** 그래프에 없는 전제가 붙은 2건은 '확인 필요'로 남았고, 리허설에서 통과한 2건은 기각됐다. 점수·끊김 판정은 바뀌지 않았다.

## 한계

- 1회 실행, 가상 회사 1곳이다. 실제 회사 문서에서의 정밀도·재현율은 아직 재지 않았다.
- 같은 입력으로 다시 돌리면 다른 가설이 나올 수 있다. 판정은 결정적 리허설이라 같은 가설이면 같은 상태가 나온다.
