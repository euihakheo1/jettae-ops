## 13. LLM 조건(C·D·DR) 실행 방법

C·D·DR은 실제 모델을 호출하므로 `ANTHROPIC_API_KEY`가 필요하고 비용이 듭니다. 이 저장소의 결과는 API 키 없이 만든 것이라 세 조건은 테스트(가짜 LLM)로만 검증되었고 수치가 없습니다. 하네스는 `llm` 인자를 명시하지 않으면 LLM 조건을 거부하고, 실행 전에 호출 수·토큰 추정치를 먼저 출력합니다.

```powershell
# 1) 비용 추정만 (호출 없음)
python -m jettae.evalkit --conditions C_llm_direct,D_llm_graph,DR_hybrid --estimate-only

# 2) 실제 실행 (유료). 모델은 JETTAE_ANTHROPIC_MODEL(기본 claude-opus-5-5)
$env:ANTHROPIC_API_KEY = "<발급받은 키>"
python -m jettae.evalkit --out docs/eval --generated-at <YYYY-MM-DD> `
  --conditions A_keyword,B_rule_graph,O_oracle,C_llm_direct,D_llm_graph,DR_hybrid --confirm-paid
```

- D와 DR은 사례마다 LLM 추출 한 번을 공유합니다(DR = 같은 LLM 출력 + 규칙 추출). 비교가 짝지어지고 비용은 한 번만 듭니다.
- 역번역 대조는 모든 조건에서 슬롯 대조만 씁니다. LLM 동등성 판정은 간선을 보류할 수만 있고, 빼면 조건 간 차이가 추출에서만 생깁니다.
- C는 고정 10종 결함 목록(스키마 열거형)에서만 고르고, 카탈로그에 없는 서비스 이름은 버립니다.

전체 코퍼스 추정치(모델 `claude-opus-5-5`, 토큰 = 글자 수 / 2.5, 출력은 경험값):
