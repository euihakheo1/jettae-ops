# AI 수정 초안 재검사 통과율 · 명부 외 인물 생성 — 측정 계획 (사전 등록, 2026-10-18)

신청서 KPI 결함 탐지(봉인셋) 줄의 "AI 수정 초안 재검사 통과율·명부 외 인물 생성"(목표 90% 이상 / … / 0건)과
계획 문구 "④ 개선: 끊긴 곳마다 AI가 고칠 문장 초안 → 과거 리허설 재실행 통과 → 팀 리드 승인분만 새 버전"을
봉인 평가셋에서 잰다. 결과가 어떻게 나와도 공개한다.

순서를 그대로 적는다: LLM을 끈 무료 실행(템플릿 초안)은 이 문서보다 먼저 돌렸다(아래 "무료 실행 결과").
이 문서가 사전 등록하는 것은 **아직 돌리지 않은 유료 실행(LLM 초안)** 의 표본·모델·지표·해석 규칙이다.

## 도구

- `scripts/eval_patch_recheck.py` (src/ 밖, 제품 패키지를 불러 씀). 제품 코드는 동결 커밋 `ccf3b4d` 그대로다
  (`git diff --quiet HEAD -- src/` 통과).
- 코퍼스: 봉인 평가셋 `kit.build_cases(kit.generate_gold_orgs(20, 20261012), seed=20261012)` — 생성기
  `jettae-evalkit-gen/1.1.0`, 조직 20곳, 1,320건(변이 1,200 + 정상 대조군 120).
- 표본: `jettae eval run --sample`과 같은 결정적 표본(`kit.reproducibility_sample`, 사례 id SHA-256 순서).
  작은 비율은 큰 비율의 부분집합이다.

## 사례 하나에서 일어나는 일

1. 그래프를 두 가지로 만든다. **B** = 평가 하네스 조건 B와 같은 제품 LLM 끔 경로(입력 검사 → 규칙 파서 →
   조립 → 슬롯 역번역 대조). **O** = 정답 사실을 그대로 그래프로 만든 것(추출 오류 없는 상한).
2. 진단 단계를 제품 파이프라인과 같은 함수로 돌린다: 고정 규칙 → 그 그래프의 템플릿 훈련 생성 → 결정적 리허설.
3. 초안: `TemplateDrafter`(LLM 없음) 또는 `LlmDrafter`(LLM이 문장을 다시 쓰고 같은 후보 목록에서 사람을 고름;
   그래프 연산은 어느 쪽이든 코드가 만든다).
4. 제품 검증(`validate_drafts` → `validate_patch`): 수정 전후 고정 규칙 재검사, 수정 전 그래프에서 돈 훈련을
   수정 후 그래프에서 다시 돌림(통과 → 실패 = 회귀), 명부 대조, 출처 표기.
5. 이 스크립트가 따로 하는 대조: 수정안이 추가·연결·수정하는 인물을 사례의 명부 CSV(표준 `csv` 모듈로 직접 읽음)에서
   다시 찾고, 수정안 문장 속 '이름 + 직함'을 명부와 대조하고, 수정 후 그래프에 고정 규칙을 다시 돌려 "해소됐다"는
   끊김이 정말 사라졌는지 확인한다. 이 검사기들은 실행마다 양성 대조(지어낸 이름·퇴사자를 일부러 넣어 잡히는지)를 먼저 돈다.
6. 보조 모의: 통과 수정안을 하나씩 승인 → 제품의 승인 후 재판정(`evaluate_graph`) → 다시 초안·검증, 통과안이 없을 때까지.

## 정의

- **수정안** = 그래프 연산이 있는 초안. **검토 메모** = 연산이 없는 초안(감지 설계, 롤백 절차, 명부에 없는 연락 수단,
  같은 팀 후보가 없는 담당 지정 등 사람이 정해야 하는 것). 제품은 메모에 승인 버튼을 주지 않는다.
- **재검사 통과** = 제품 검증기의 `passed`: 연산이 그래프에 적용되고, 수정안이 만든 요소의 출처가 그 수정안으로 적혀 있고,
  통과하던 리허설이 실패로 바뀌지 않고, 명부 외 인물이 없고, 겨냥한 끊김을 하나 이상 해소하고, 높음 이상 새 끊김이 없을 것.
- **재검사 통과율(주 지표)** = 통과 수정안 / 수정안. 보조: 엄격 통과(겨냥한 끊김 전부 해소 + 새 끊김 0건),
  메모까지 분모에 넣은 비율, 같은 결정 단위(조직 × 결함 연산자 × 수정 유형) 통과율, 조직 20곳 복원추출 부트스트랩 구간
  (렌더 6개가 같은 결정을 다시 묻기 때문에 수정안끼리 독립이 아님).
- **명부 외 인물 생성(목표 0건)**, 네 가지를 따로 센다:
  1) 검증기 집계(`unknown_people`) 2) 명부 CSV 독립 대조 — 명부에 없음 · 재직 아님 · 동명이인인데 팀으로도 가려지지 않음
  3) 수정안이 인물 노드를 새로 만든 수 4) 문장 속 '이름 + 직함' 중 명부에 없는 것.
- 끊김 기준: 각 끊김이 수정안 / 메모 / 초안 없음 중 어디로 갔는지, 통과 수정안이 실제로 해소했는지.
  주입 결함 기준: 목표 서비스에서 기대 규칙으로 나온 끊김만 따로.
- 조건별(B, O), 결함 연산자별, 문체별, 수정 유형별로 보고한다.

## 유료 실행(LLM 초안) — 사전 등록, 아직 실행하지 않음

- 명령:
  `JETTAE_ANTHROPIC_MODEL=claude-sonnet-5-5 python -X utf8 scripts/eval_patch_recheck.py --llm --sample 0.2 --yes --max-usd 10`
  (`--yes`가 없으면 추정만 출력하고 거부한다. 키는 `ANTHROPIC_API_KEY`를 환경 변수 또는 `.env`에서 유료 경로 안에서만 읽고 출력하지 않는다.)
- 표본: 결정적 20%(264건). 조건: **B만**. 모델: `claude-sonnet-5-5`(2×2 실험의 추출 모델과 같음), effort `medium`
  (제품 기본값), `LlmDrafter` 기본 max_tokens 2,000, 동시 사례 4.
- 모델 주의: 제품 설정의 기본 모델은 `claude-opus-5-5`다. 이번 측정은 2×2와 맞추려고 `claude-sonnet-5-5`로 한다.
  결과는 Sonnet 5.5가 쓴 초안의 값으로 적고, 제품 기본 모델의 값이라고 쓰지 않는다.
- 왜 B 그래프인가: 추출은 LLM 없이 두고 초안 문장만 LLM에게 맡겨, 같은 끊김·같은 후보 목록에서 템플릿 초안과 짝 비교한다.
  LLM 추출 그래프(D·DR) 위의 초안은 추출 비용이 더해지므로 이번 범위에서 뺀다.
- 추정(오프라인으로 같은 요청을 다시 만들어 셈, 정가): 호출 132회, 입력 약 458K 토큰(글자 수/1.0, 보수적), 출력 최대 264K
  토큰(호출당 max_tokens 2,000 상한) → **약 $3.56**. 모든 호출이 형식 오류로 한 번씩 재요청되는 최악 $7.82. 예산 상한 $10.
  참고: 10% 표본 63회 약 $1.70, 전수 696회 약 $18.77.
- 보고할 지표: LLM에 보낸 수정안 수, LLM 문장 채택 수, 템플릿으로 되돌아간 수와 사유(호출 실패·잘림 / 제품이 문장을 거부),
  **LLM 문장 수정안의 재검사 통과율(주 지표)**, 명부 외 인물 네 가지, 같은 끊김의 템플릿 초안과의 판정 비교, 실제 지출.
  출력: `C:/jettae/data/eval/patch-recheck-llm/`.
  '호출 실패·잘림'에는 응답이 형식에 맞지 않아 제품 어댑터가 받지 않은 경우(후보 목록 밖 id를 고른 응답 등)도 들어간다.
  오류 종류별 횟수(`LLMError`·`LLMOutputError`·`LLMRefusalError` 등)는 따로 적는다.
- 사전 점검(호출 0회, 2026-10-18): 유료 경로(LLM 초안 → 제품 검증 → 집계 → 보고서)를 가짜 모델로 오프라인에서 끝까지
  돌렸다. 결정적 10% 표본에서 결함 연산자마다 2건씩 22건(B), LLM에 보낼 수정안 13건. 확인한 것: 템플릿 문장을 그대로
  돌려주면 AI 문장으로 채택되어 검증까지 간다 / 문장에 지어낸 '홍길동 팀장'을 넣으면 13건 모두 제품이 거부하고 템플릿으로
  되돌아간다 / 후보 목록 밖 id를 고르면 형식 오류로 거부된다 / 호출이 실패하면 템플릿이 남는다 / 예산 상한이 한 호출의
  예약액보다 작으면 아무 호출도 보내지 않고 멈춘다. 이것은 배관 점검이고 LLM 성능 값이 아니다.
- 실행 중 크레딧이 떨어지는 경우(2026-10-18 추가, 결과 보기 전): 요청이 답을 받지 못하면(크레딧·키·속도 제한·네트워크)
  그 뒤 요청은 보내지 않고 실행을 '중단됨'으로 보고한다(나머지 수정안은 `not_sent`로 템플릿이 남는다). 전에는 남은 표본이
  조용히 템플릿으로 되돌아간 채 '끝난 실행'으로 보였다. 잘림·형식 오류·거부는 모델의 답이므로 멈추지 않는다. 중단된 실행의
  AI 통과율은 LLM 문장이 채택된 수정안에 대한 값일 뿐이므로, 표본을 다 채우려면 충전 뒤 다시 실행한다(이어하기 없음).
- 해석 규칙:
  - 표본 결과는 표본 결과로 쓰고 1,320건 값이라고 하지 않는다.
  - 'AI 수정 초안 통과율'의 분모는 LLM 문장이 채택된 수정안이다. 템플릿으로 되돌아간 것은 AI 초안으로 세지 않고 따로 적는다.
  - max_tokens 2,000 안에서 사고 토큰 때문에 응답이 잘려 템플릿으로 되돌아가는 비율이 높아도 그대로 공개한다.
    결과를 본 뒤 effort·max_tokens·프롬프트를 바꿔 다시 돌리지 않는다(바꾸면 새 계획으로 따로 등록).
  - 추정과 실행 사이에 코드·설정·프롬프트를 바꾸지 않는다.
  - 명부 외 인물이 1건이라도 나오면 사례 id와 문장을 그대로 공개한다.

## 이 측정이 보여 주지 않는 것

- 실제 조직 런북에서의 통과율(봉인셋은 합성 조직 20곳).
- 사람이 만든 훈련·LLM이 제안한 훈련에 대한 회귀(이번 리허설은 제품이 자동 생성한 템플릿 훈련만).
- 명부 자체가 틀린 경우(모든 명부 대조가 같은 명부 CSV를 기준으로 한다).
- 팀 리드가 실제로 승인할지(검증 통과는 '승인 버튼이 뜰 자격'이지 승인이 아니다).
