## 해석 (정직하게)
- **신청서 가설은 이 합성셋에서는 맞지 않았습니다.** 신청서는 "구어체에서 규칙 파서가 무너지는 폭이 AI 필요 근거"라고 했지만, 규칙 파서(B)는 구어체에서도 62/63을 잡았습니다. 이 규칙 파서는 같은 생성기로 만든 개발 분할로 다듬었으므로, 생성기 문체에 익숙한 효과일 수 있습니다(`../report.md` 15절). 실제 공개 런북(실증 ①)에서는 규칙 파서가 거의 기여하지 못하고 그래프는 LLM 추출이 만듭니다.
- **LLM만으로 추출하면(D) 정상 문서에서 오탐이 납니다.** 28건 모두에서 심각 경보가 나왔습니다. 문서에 있는 요소를 LLM이 일부 빠뜨리면 고정 규칙이 그 요소를 '없음'으로 판정하기 때문입니다. 규칙 추출과 합치면(DR) 오탐이 3/28로 줄고 탐지는 96.9%입니다. **하이브리드(DR)가 제품의 LLM 켬 기본값인 이유**가 여기서 보입니다.
- **그래프 없이 LLM에게 직접 묻기(C)는** 탐지 85.1%에 오탐이 35.7%입니다. 구어체에서는 40/63으로 가장 약합니다.
- **봉인셋은 합성 데이터입니다.** 결론은 "AI가 더 정확하다"가 아니라, "이 합성 문서에서는 규칙 파서가 충분하고, LLM 단독 추출은 오탐을 만들며, 둘을 합친 것이 LLM을 켤 때의 안전한 기본값"입니다.

## 실행 경과와 비용
- **시험 실행:** 2%(27건)로 비용만 쟀습니다(약 $3.0, 지표는 보고하지 않음).
- **본 실행:** 실행 도중 선불 크레딧이 떨어져 C 97쌍, D·DR 103사례가 HTTP 400으로 거절됐습니다.
  - `scripts/eval_llm_resume.py`로 그 쌍만 같은 설정으로 다시 돌려 합쳤습니다. 재실행 중에도 한 번 더 크레딧이 떨어졌고, 저장된 결과에서 이어서 돌렸습니다.
  - 합친 결과의 필드 F1·누락 필드 환각은 '첫 실행 합계 − 거절된 사례의 기여 + 재실행 기여'로 정확히 계산했습니다. 오프라인 조건 B로 자체 검증을 통과했습니다(`--self-test`).
  - 바뀐 쌍과 두 오류 문구는 `merge_log.json`에 있습니다.
