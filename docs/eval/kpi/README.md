## 항목별 요약

**AI 기여 분리(2×2)** (`../llm-2x2-sample20/`)
- 봉인셋(합성)의 결정적 20% 표본 264건, `claude-sonnet-5-5`(effort medium). 규칙 파서 B가 구어체 활성 결함도 62/63을 잡아, "구어체에서 규칙 파서가 무너지니 AI가 필요하다"는 신청서 가설은 이 합성셋에서 지지되지 않았습니다. 규칙 파서는 같은 생성기로 다듬었으므로 생성기 문체에 익숙한 효과일 수 있습니다(아래 재서술 시험).
- LLM만으로 추출하면(D) 정상 문서 28건 모두에서 심각 경보가 났고, 규칙 추출과 합치면(DR) 3/28로 줄었습니다. LLM 켬 기본값이 하이브리드(DR)인 이유입니다.
- 크레딧이 실행 중 떨어져, 거절된 쌍만 같은 설정으로 다시 돌려 정확히 합쳤습니다(`scripts/eval_llm_resume.py`, 자체 검증). 비용 약 $32(시험 실행 약 $3 포함).

**AI 수정 초안 재검사** (`patch-recheck/`, `patch-recheck-llm/`)
- 템플릿(LLM 끔) 수정안은 봉인셋 1,320건 전수에서 732/816 = 89.7%가 재검사(고정 규칙 재검사 + 리허설 무회귀 + 명부 대조)를 통과했습니다.
- LLM(Sonnet 5.5) 문장 수정안은 20% 표본에서 112/129 = 86.8%가 통과했습니다. 같은 끊김의 템플릿 초안과 짝 비교한 165쌍은 판정이 모두 같았습니다. 그래프 변경은 코드가 만들고 LLM은 문장만 바꾸기 때문입니다. 비용 $1.10.
- 실패는 모두 한 유형입니다. 퇴사자 담당을 넘겨받은 사람에게 상향 경로가 없어 새 높은 끊김이 생기는 경우이고, 검증기가 승인을 막습니다.
- 끊김의 26%는 사람이 정해야 해서 연산 없는 검토 메모로 갑니다(감지 설계, 롤백 절차, 같은 팀 후보가 없는 담당자 지정 등). 메모까지 분모에 넣으면 통과율은 약 54%입니다.

**사람 수정 반영(숨은 규칙 복원)** (`hidden-rule/`)
- 숨은 규칙 3개로 합성 승인 기록을 만들고, 기록에 쓰지 않은 모의 장애에서 정답 그래프와 같게 움직이는지 봤습니다.
- 현재 API처럼 팀장이 승인·거절만 할 때 동치율은 74.1%입니다. 수정안을 직접 고칠 수 있다면(현재 API에는 없음) 98.6%입니다.
- **제품은 기록에서 배우지 않습니다.** 기록이 없는 범위 서비스의 동치율은 기록 전후 모두 18.8%로 같았습니다.
- 미승인 변경은 그래프에 들어가지 않았습니다(차단 시도 10종 × 50건 모두 거부). 이력 위반 0건, 되돌리기 50/50.

**다른 계열 모델 재서술** (`paraphrase/`)
- 신청서는 봉인셋 표현 3종을 다른 계열 모델이 재서술한다고 했지만, 실제 봉인셋은 생성기 템플릿 문체였습니다.
- 봉인셋 표본 180건을 OpenAI `gpt-6-luna`가 같은 문체로 고쳐 썼습니다(예산 때문에 계획의 gpt-6.1-sol 대신, 실행 전 기록). 사실 보존 관문을 138건(76.7%)이 통과했고, 비용은 $0.22입니다.
- 같은 사례에서 규칙 파서(B)는 결함 탐지 98.7% → 82.9%(McNemar p = 0.0005), 정상 문서 오탐 0% → 91.3%, 필드 F1 0.9999 → 0.754로 떨어졌습니다.
- 뜻: 봉인셋의 96.5%·오탐 0%는 규칙 파서가 생성기 문장에 익숙해서 나온 값입니다. 낯선 문장에서는 규칙 파서만으로 부족합니다. 실제 공개 런북(실증 ①)에서 그래프를 LLM 추출이 만드는 이유와 같습니다.
- LLM 조건(D·DR)을 재서술본에 돌리는 짝 비교는 예산이 없어 하지 않았습니다.

**실문서 결함 주입(축소판)** (`real-inject/`)
- 신청서의 봉인셋 설계(공개 런북 번안, 기존 결함은 분모에서 분리)를 실제 문서로 줄여 해 봤습니다. 실증 ①의 GitLab 런북 한국어 충실 번역판에서 특정 서비스의 담당·상향·승인·완화 조치 문장을 줄 단위로 지우고, 제품이 그 서비스에 새 지적을 내는지 봤습니다.
- 지점은 AI(Claude)가 고르고 다른 Claude 에이전트가 점검했습니다. 기대 규칙을 정할 수 없는 2개를 빼고 남은 지점은 문서 2건의 4개뿐입니다.
- B(LLM 끔): 0/3. 규칙 파서가 두 문서에서 서비스를 하나도 읽지 못해 검사할 대상이 없었습니다(1개는 기존 결함으로 분모에서 뺌).
- DR(LLM 켬): 4개 중 3개는 원본에서 이미 같은 지적이 떠 분모에서 빠졌고, 남은 1개(상향 삭제)를 놓쳐 0/1입니다. 비용 약 $0.14.
- 분모가 너무 작아 일반화할 수 없는 사례 보고입니다. 봉인셋 결과를 대신하지 않습니다.

## 남은 차이 (신청서와)
- 봉인셋의 기준 런북은 공개 런북 번안·공공누리 매뉴얼이 아니라 생성기의 합성 조직 20곳입니다. 신청서의 '기준 런북 20개 × 표현 3종(다른 계열 모델이 재서술)'은 봉인셋 설명이었지만, 실제 봉인셋의 문체 3종은 생성기 템플릿입니다. 대신 실데이터 실증(GitLab 원문과 한국어 충실 번역판, [`../realdata-results.md`](../realdata-results.md)), 다른 계열 모델 재서술 시험, 실문서 결함 주입 사례 보고를 했습니다.
- 실문서 결함 주입(번역판 문서 2건)을 빼면 위 측정은 모두 합성 조직 기준입니다. 실제 회사의 승인 행동이나 한국 조직이 쓴 런북은 재지 않았습니다.
