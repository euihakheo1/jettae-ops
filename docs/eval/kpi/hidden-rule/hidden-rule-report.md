## 진단 경로: 런북 → 규칙 파서(LLM 끔) → 기록 → 무관한 줄 수정 뒤 재진단

기록을 오라클 그래프가 아니라 제품이 런북에서 추출한 그래프 위에서 만들고, 무관한 줄(첫 서비스의 알람 지연 분)을 고쳐 다시 진단한 뒤에도 승인분만 남는지 봅니다. 정답도 정답 런북을 제품이 직접 진단해 만든 그래프입니다.

- 무관한 줄 수정으로 추출 그래프가 바뀌고 재진단이 새 버전을 만든 경우: 102/102 (= 승인분을 새 추출 그래프에 다시 얹는 경로를 실제로 거침)

- '거절한 초안 재제안'은 재진단 뒤 같은 내용의 초안이 다시 '검증 통과'로 올라온 수(거절한 서로 다른 초안 수 대비)입니다. 제품은 거절 사유를 기억하지 않으므로, 끊김이 남아 있으면 같은 초안이 다시 나오고 팀장이 다시 거절해야 합니다.

## 덤: 템플릿 수정안(LLM 끔)의 재검사 통과·명부 외 인물

- 사례마다 규칙 적기 전 그래프에서 처음 만든 초안 112건 중 연산 있는 것 112건, 재검사(검증) 통과 112건, 명부 외 인물이 든 초안 0건.
- 모든 세션이 만든 템플릿 초안(중복 포함) 850건 중 통과 850건, 명부 외 인물 0건, 검토 메모(연산 없음) 0건.
- **AI(LLM) 초안 수치가 아닙니다.** 신청서의 'AI 수정 초안 재검사 통과율'은 LLM이 문장을 다시 쓰고 후보를 고르는 경로라 유료 실행이 필요합니다.
- 같은 첫 초안을 AI가 다시 쓰면 보낼 요청(오프라인 계산): 숨은 규칙 사례 112회 — claude-haiku-5-5 $0.14, claude-sonnet-5-5 $2.80, claude-opus-5-5 $5.60; 봉인셋 결함 200종(조직×연산자)의 오라클 그래프 114회 — claude-haiku-5-5 $0.14, claude-sonnet-5-5 $2.80, claude-opus-5-5 $5.60 (정가, 가격표 2026-10-14; 입력 토큰 = 글자 수(한국어 1글자 ≈ 1토큰, 저장소 가격표의 보수적 비율) · 출력 = 호출당 2,000토큰(LlmDrafter max_tokens 상한, 사고 토큰 포함) · 캐시 할인 없음)

## 한계

- 규칙 3개, 조직 20곳의 합성 기록입니다. 실제 팀의 수정 이력이 아니고, 팀장 판단도 시뮬레이션입니다.
- 동치는 공개된 리플레이 가정(응답 5분, 승인 5분, 감지 지연 기본 5분 등) 안에서의 동치입니다. 실제 장애에서 같은 결과를 보장하지 않습니다.
- 제품이 끊김으로 찾지 못한 규칙 조항은 수정안으로 넣을 수 없습니다(검증이 '해소한 끊김이 하나 이상'을 요구). 예: 3등급 서비스의 상향·승인 규칙(해당 규칙은 핵심 등급만 봄). 이 경우 길은 런북을 고쳐 다시 진단하는 것뿐입니다.
- '직접 고친 수정안' 팔(rule_edit)은 도메인 함수로만 가능한 경로를 흉내 낸 상한입니다. 지금 API·화면에는 사람이 수정안 내용을 고치는 기능이 없습니다.
- 규칙 아는 팀장 두 팔의 '과대 0'은 가상 팀장이 '그래프를 정답 쪽으로만 바꾸는 초안만 승인'하도록 정한 결과라 구조상 0입니다. 제품이 보장하는 것은 '승인한 수정안의 연산 말고는 그래프에 들어가지 않는다'(이력 재구성 위반 0)까지이고, 과대 적용이 생기는지는 팀장이 무엇을 승인하느냐에 달려 있습니다(규칙 모르는 팀장이 전부 승인하면 과대가 생김).
- '범위 밖 서비스 그래프 변경 0'은 합성 조직의 범위 밖 서비스에 처음부터 끊김이 없어 초안이 나오지 않았기 때문이기도 합니다(전부 승인 팔도 0). '규칙의 범위를 알아서 지킨다'는 뜻이 아니라 '끊김이 없는 서비스는 건드리지 않는다'는 뜻입니다.
