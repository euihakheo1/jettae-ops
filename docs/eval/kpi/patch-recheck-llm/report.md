## 해석할 때 주의

- 통과율의 분모는 '연산 있는 수정안'이다. 검토 메모(감지 설계·롤백 절차처럼 사람이 정해야 하는 것, 명부에서 후보를
  못 찾은 것)는 제품이 일부러 승인 버튼을 주지 않는 초안이라 분모에서 뺐고, 메모 비율은 따로 적었다.
- 검증기의 명부 외 인물 0건은 설계상 기대값이다(초안 작성기와 검증기가 같은 명부 대조 규칙을 쓴다). 그래서 이 스크립트가
  명부 CSV를 표준 라이브러리로 따로 읽어 수정안이 연결하는 사람을 다시 대조했다. 이 역시 같은 명부에서 나온 값이라
  '명부 자체가 틀린 경우'는 잡지 못한다.
- 문장 속 이름 검사는 '이름 + 직함' 꼴만 본다. 직함 없이 이름만 지어낸 문장은 이 검사로 못 잡는다(템플릿 문장은 코드가
  명부 이름으로 만들기 때문에 해당 없음; LLM 문장은 제품이 별도로 막는다).
- O(정답 그래프)는 추출 오류가 없는 상한이다. B 값이 제품의 LLM 끔 경로 값이다.
- 검토 메모는 제품 설계상 승인 버튼이 없는 초안이다: 감지 신호·롤백 절차는 사람이 정해야 하고, 연락 수단은 명부에
  등록된 것만 쓰며(지어내지 않음), 담당자가 사라진 서비스에 같은 팀 재직자를 찾지 못하면 CTO·대표 같은 최종 책임자를
  1차 담당으로 넣지 않는다(새 단일 장애점이 되므로). 그래서 해당 결함 연산자는 '수정안 0건'으로 나온다.
