# AI 기여 분리(2×2) — 실행 전 계획 (사전 등록, 2026-10-18)

신청서 KPI 첫 줄("AI 기여(2×2): 추출(규칙 파서/LLM) × 검사(없음/그래프) + 역번역 대조, 조건별·표현 유형별
필드 정확도·탐지율 / 결측 환각률 / 원문 근거 위치 없는 필드 — 측정값 공개")을 봉인 평가셋에서 잰다.
이 문서는 결과를 보기 전에 커밋한다. 결과가 어떻게 나와도 공개한다.

## 설계
- 코퍼스: 봉인 평가셋(생성기 `jettae-evalkit-gen/1.1.0`, 시드 20261012, 조직 20곳, 1,320건).
  동결 코드로 다시 만든 사례는 공개 봉인과 같다(`scripts/sealed_set_recheck.py`, 정책 YAML 기본값 두 줄 차이만).
- 조건: A 키워드(그래프 없음) · B 규칙 파서 + 그래프(LLM 끔) · C LLM 직접 판정(그래프 없음) ·
  D LLM 추출 + 그래프 · DR 규칙 ∪ LLM 추출 + 그래프 · O 정답 그래프(판정 규칙 상한).
  D와 DR은 사례마다 LLM 추출 한 번을 공유한다. 역번역 대조는 모든 조건에서 슬롯 대조만 쓴다(하네스 기본).
- 모델: `claude-sonnet-5-5`, effort medium(실증 ①과 같은 추출 모델). 제품 코드는 동결 커밋 `ccf3b4d` 그대로
  (`src/` 변경 없음).
- 표본: `jettae eval run --sample`의 결정적 표본(사례 id 해시 순서, 작은 비율은 큰 비율의 부분집합).
  1) 시험 실행 2%로 실제 건당 비용만 잰다(지표는 보고하지 않음, 본 표본에 포함됨).
  2) 본 실행 비율은 시험 실행의 실제 건당 비용으로 정한다: 예상 비용이 $8 이하인 비율 중 가장 큰 것
     (20%, 30%, 50%, 100% 중). 20%도 $8를 넘으면 20%로 하고 추가 충전 뒤 실행한다.
- 시험 실행과 본 실행 사이에 코드·설정·프롬프트를 바꾸지 않는다.

## 보고할 지표 (조건별, 문체별)
- 활성 결함 탐지율, 보류(봉인) 결함 탐지율, 정상 대조군 오탐률 — Wilson 95% 구간
- 필드 정밀도·재현율·F1, 누락 필드 환각률(지운 사실을 되살린 비율), 원문 근거 위치 없는 요소 수
- 핵심 비교: 구어체에서 B(규칙) 대비 D·DR(LLM 추출 + 그래프), D 대비 C(그래프 없이 LLM 직접 판정)
- 비용(실제 지출)과 호출 수

## 해석 규칙
- 표본 결과는 표본 결과로 쓰고 전체 1,320건 값이라고 하지 않는다.
- C가 B·D만큼 잘 나와도 그대로 공개한다. 그 경우 그래프의 가치는 정확도가 아니라 재현성·근거·증적으로 설명한다.
- 10/14에 공개한 오프라인 수치(A·B·O)는 바꾸지 않는다. 본 실행의 A·B·O는 표본 값으로 따로 적는다.

## 실행 기록 (2026-10-18, 결과 보고 전에 덧붙임)
- 시험 실행 2%(27건): 실제 사용량 기준 약 $3.0(건당 약 $0.11). D 추출의 출력이 건당 약 9,400토큰으로, 사전 추정보다
  약 2.5배 컸다. 미리 정한 규칙대로 본 실행은 20%(264건)로 하고 충전 뒤 실행했다. 시험 실행 지표는 보고하지 않는다.
  (처음 시도한 시험 실행은 실행 스크립트에 Windows 다중 프로세스 보호 코드가 빠져 작업 프로세스가 시작되지 못해 중단했다.
  결과 폴더는 생기지 않았다.)
- 본 실행 20%(264건): 실행 도중 Anthropic 선불 크레딧이 떨어져, LLM 조건의 일부 요청이 HTTP 400("credit balance is
  too low")으로 거절됐다(D·DR 103건, C 97건). 그때까지 쓴 금액은 약 $17.3이다.
- 처리 방법(결과를 보기 전에 정함): 충전 뒤 **크레딧 때문에 거절된 (사례, 조건) 쌍만** 같은 코드·모델·설정으로 다시
  실행해 합친다(D와 DR은 함께). 내용 때문에 실패한 17건(출력 길이 초과로 잘림 11건(C), 응답 거절 6건(D·DR))은
  다시 돌리지 않고 오류 그대로 집계한다. 첫 실행 결과 파일에는 사례별 사실 목록이 없으므로, 필드 정확도·누락 필드
  환각은 첫 실행 합계에서 거절된 사례의 기여(사실 0개)를 빼고 재실행 기여를 더하는 방식으로 정확히 합친다
  (`scripts/eval_llm_resume.py`, 오프라인 조건 B로 같은 방식이 정확한지 자체 검증).
