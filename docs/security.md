# 보안·개인정보 설계

## 데이터 흐름과 보관
| 데이터 | 처리 | 보관 |
|---|---|---|
| 런북 원문 | 업로드 즉시 정규화 → **길이 보존 PII 마스킹**(휴대폰·이메일·IP·주민번호·카드) → 인젝션 격리 | 기본 **원문 비저장**(`JETTAE_STORE_RAW_DOCUMENTS=false`): 해시·제목·격리 구간만 저장. 근거 하이라이트가 필요하면 `true`로 켜고, 그때도 마스킹된 원문만 저장 |
| 명부·당직표 | 이름·직급·팀·역할·재직 상태·연락 수단 **종류**만 사용(번호 자체는 쓰지 않음). 이름·재직 상태·역할·연락 수단 종류·퇴사일은 사람을 맞춰 보는 진단에 필요하므로 가리지 않는다. 무료 검진에서는 직급·팀·별칭 같은 자유 글자를 그래프에 넣기 전에 길이 보존 PII 마스킹 | 고객별 워크스페이스. 공개 사이트의 무료 검진은 진단이 끝나면 입력 파일 자체를 버리고, 그래프에 들어간 값만 결과와 함께 7일 보관 |
| 카탈로그·정책 | 서비스·시스템·채널·위치·의존 관계. 무료 검진에서는 설명·담당(owner)·위치 같은 **자유 글자를 그래프에 넣기 전에 길이 보존 PII 마스킹**(서비스 이름·별칭·의존 관계·종류·등급처럼 진단이 맞춰 보는 값은 그대로) | 무료 검진은 입력 파일을 버리고 그래프의 마스킹된 값만 결과와 함께 7일 보관 |
| 그래프 | 원문 위치(span)와 마스킹된 인용만 포함 | 버전별 content-addressed |
| LLM 호출 | 마스킹·격리된 텍스트만 전송. 설치형은 vLLM 로컬 모델로 외부 전송 없음 | 호출 수·토큰만 기록(내용 미기록), 데모용 카세트는 명시적 녹화 시에만 |
| 사전 신청 | 이메일·조직명·팀 규모·남긴 말, 개인정보 수집·이용 동의 필수, 마케팅 동의 별도 | **1년**(`JETTAE_SIGNUP_RETENTION_DAYS`) 뒤 서버가 삭제, 철회 요청 시 즉시 삭제(`DELETE /api/v1/signups/{email}`, `admin`). 명단 조회·내려받기는 `admin`만, 조회마다 감사 로그(누가·몇 건·형식) |
| 무료 검진 결과 | 접근 키로만 열리는 비공개 워크스페이스 | **7일**(`JETTAE_FREE_SCAN_RETENTION_DAYS`) 뒤 워크스페이스째 삭제. 실패한 검진은 바로 삭제 |
| 수요 측정 이벤트 | 허용된 이름, 이벤트별로 정해진 값(열거형·정수 범위·참거짓), 정해진 화면 경로(`/`·`/app`·`/app/report`·`/privacy`) 중 하나만 — 자유 글자가 없어 개인정보가 들어갈 자리가 없음 | 사이트 전체 하루(한국 시간) `JETTAE_EVENTS_PER_DAY`(공개 사이트 20,000)건까지만 저장(넘으면 202로 답하되 버림). DB가 있는 동안 보관 |
| 워크스페이스 접근 키 | 무료 검진 응답으로 한 번만 보내고, 브라우저가 보관 | SHA-256 해시만 저장(원래 키는 운영자도 복원 불가) |
| 방문자 접속 주소(IP) | 접속 주소당 횟수 제한의 열쇠로만 사용(아래 「방문자 주소」) | 서버 메모리의 횟수 계산에만 있고 로그·DB에 남기지 않음 |

## 무료 검진 경로
- **GitHub Action판**: 고객 저장소 안에서 실행된다. 고정 규칙 검사는 LLM 없이 돌고, AI 추출은 고객의 API 키로 돈다.
  제때옵스는 원문과 비용을 받지 않는다. 결과는 SARIF로 GitHub 코드 스캐닝에 표시된다.
- **웹판**: 연락처·주민번호 등 자동 가림, 원문 비저장, 아래 「공개 베타의 위협 모델과 통제」의 한도.
  공개 사이트(`POST /api/v1/free-scans`)는 검진마다 비공개 워크스페이스를 만들고 **접근 키**를 돌려준다.
  워크스페이스 id는 식별자일 뿐 비밀이 아니므로(결정적으로 만들어지고 URL·로그에 남음) 권한 판단에 쓰지 않는다.
  공개 사이트는 LLM을 끈 채 운영한다(`JETTAE_LLM_MODE=off`, 이미지에 AI SDK도 없음): 방문자 런북이 외부 LLM으로
  나가지 않는다. 검진이 끝나면 런북 원문을 프로세스 메모리에서도 지우고, 명부·카탈로그 같은 구조화 입력도 버린다.
- **마스킹 범위**: 런북 본문, 카탈로그의 설명·담당·위치, 명부의 직급·팀·별칭은 길이 보존 마스킹(연락처·이메일·IP·
  주민번호·카드 모양만 가림)을 거친다. 명부의 이름·재직 상태·역할·연락 수단 종류는 진단(담당자 확인·부재 리허설)에
  쓰이므로 가리지 않고 그래프에 들어간다 — 그래서 무료 검진 결과에는 이름이 남을 수 있고, 결과와 함께 7일 뒤
  삭제된다(처리방침 `/privacy`에 고지). 마스킹은 정해진 모양만 찾으므로 자유 글자 속 사람 이름은 가리지 못한다.
- **예제**: 별빛상점 예제는 서버가 시작할 때 한 번 진단해 둔다. 방문자가 예제를 열거나 다시 진단을 요청해도 새로
  진단하지 않고 저장된 보고서를 돌려주므로, 예제 클릭이 CPU·DB·무료 검진 한도를 쓰지 않는다.

## 권한
- 역할은 `viewer`, `editor`, `lead`, `admin`이다. 수정안 **승인·거절·되돌리기는 `lead`/`admin`만** 할 수 있다.
- 모든 상태 변경은 감사 로그(append-only)에 남는다.
- 운영 모드에서는 `JETTAE_AUTH_MODE=token`(Bearer 토큰 → 사용자·역할 매핑)을 쓴다. 개발 모드의 헤더 기반 역할은 데모 전용이다.
- 공개 베타 웹사이트는 `JETTAE_AUTH_MODE=public`을 쓴다. `Authorization` 헤더가 **없으면** 익명 보기 전용(viewer),
  올바른 토큰이면 그 역할, 헤더가 있는데 틀리면 401이다(관리자가 토큰을 잘못 넣었을 때 방문자로 강등되지 않게).
  `X-Jettae-User`·`X-Jettae-Role` 헤더는 무시한다. 토큰 표가 비어 있거나 잘못되면(16자 미만·공백 포함·모르는 역할)
  서버가 시작하지 않는다. `GET /api/v1/me`로 지금 토큰의 사용자·역할을 확인한다.
- 공개 모드의 익명 방문자는 예제 워크스페이스와, `X-Jettae-Workspace-Key`로 접근 키를 보낸 워크스페이스만 연다.
  그 밖의 워크스페이스(와 그 수정안)는 없는 id와 똑같이 404로 답해 존재 여부도 드러내지 않는다. 이 검사는 모든
  라우터에 걸린 의존성 하나가 `{ws}`·`{patch_id}` 경로 변수를 보고 하므로, 나중에 추가하는 경로도 빠지지 않는다.
  토큰을 가진 운영자는 장애 대응·악용 방지를 위해 무료 검진도 열 수 있다(개인정보 처리방침에 고지).
- 사전 신청 명단(개인정보)의 조회·삭제는 `admin`만 한다. CSV는 엑셀 수식 주입(`=`·`+`·`-`·`@`로 시작하는 칸)을 막는다.
  같은 이메일로 다시 신청해도 기존 신청(동의 시각·마케팅 동의 포함)을 덮어쓰지 않는다.
- 방문자 주소 확인용 `GET /api/v1/admin/request-info`도 `admin`만 연다(요청 헤더 속 주소를 보여 주므로).

## 방문자 주소(접속 IP)를 어디서 읽는가
접속 주소당 한도(무료 검진·이벤트·신청)의 열쇠는 `JETTAE_CLIENT_IP_SOURCE`가 정한다.

| 값 | 읽는 곳 | 쓰는 때 |
|---|---|---|
| `peer`(기본값) | uvicorn이 알려 준 접속 주소(`request.client.host`) | 프록시 없이 직접 받는 설치형·로컬 |
| `header:<이름>` | 앞단 프록시가 넣는 헤더 하나(예: `header:CF-Connecting-IP`). 헤더가 없거나 이상하면 `X-Forwarded-For`의 맨 오른쪽 값(가장 가까운 프록시가 쓴 값, 방문자가 위조할 수 없음) | 그 헤더를 프록시가 항상 덮어쓴다고 확인했을 때 |
| `xff:<n>` | `X-Forwarded-For`의 **오른쪽에서 n번째**(맨 오른쪽이 1) | 프록시가 목록 끝에 주소를 덧붙이는 구성 |

- 공개 사이트에서 `peer`를 쓰지 않는 이유: Render에서는 `X-Forwarded-Proto`를 믿어 HSTS를 붙이려고
  `FORWARDED_ALLOW_IPS="*"`를 켜는데, 그러면 uvicorn이 `X-Forwarded-For`의 **맨 왼쪽** 값(방문자가 써 보낸 값)을
  접속 주소로 삼는다. 방문자가 그 헤더에 아무 값이나 넣으면 주소별 한도를 끝없이 피할 수 있다.
- 결정: `render.yaml`은 `header:CF-Connecting-IP`로 시작한다. Render 앞단 Cloudflare가 넣는 값으로 보이지만 Render가
  문서로 보장하지 않으므로, 배포 직후 운영자가 `GET /api/v1/admin/request-info`(`admin`)로 서버가 실제로 받은
  `peer`·`x_forwarded_for`·`cf_connecting_ip`·`true_client_ip`·`x_real_ip`와 지금 설정(`client_ip_source`)·고른 주소
  (`resolved_client`)를 보고 자기 공인 IP가 실린 곳을 고른다. 그다음 같은 헤더들에 가짜 주소(`203.0.113.7`)를 넣어
  다시 불러 `resolved_client`가 바뀌지 않는지 확인한다. 꾸민 값이 통하면 `xff:<n>`처럼 앞단이 덧붙인 자리를 읽는
  설정으로 바꾼다. 절차는 [deploy.md](deploy.md) 4-2.
- 세부 규칙: 고른 헤더가 없거나 두 번 오거나 IP 주소가 아니면, 또는 `X-Forwarded-For` 항목이 n개보다 적으면 `peer`로
  센다. `X-Forwarded-For`의 n번째 값(또는 `peer`)이 IP 주소가 아니면 모두 `invalid` 한 묶음으로 센다. IPv6 주소는 `/64` 대역으로 묶어 센다(한 가정·사무실이 주소를
  바꿔 가며 한도를 피하지 못하게). `xff:<n>`의 n은 1~10이고, 형식이 틀린 값은 서버가 시작하지 않는다.
- 도메인을 붙이는 등 앞단 구성이 바뀌면 같은 확인을 다시 한다.

## 공개 베타의 위협 모델과 통제

공개 베타는 Render의 0.5 CPU · 512 MB 웹 서비스 한 대와 1 GB 무료 PostgreSQL(둘 다 싱가포르)로 운영한다.
배포 절차와 운영자 할 일은 [deploy.md](deploy.md)에 있다.

**지킬 것**: 사전 신청 개인정보, 방문자의 무료 검진 결과(명부의 이름·직급이 들어 있을 수 있음), 관리자 토큰,
한 대뿐인 서버의 가용성, 1 GB DB 용량, 수요 지표의 신뢰도.

**상대**: 로그인 없이 누구나 부르는 익명 쓰기 API(무료 검진·사전 신청·이벤트)를 스크립트로 반복 호출하는 사람,
접속 주소 헤더를 꾸며 보내는 사람, 부풀린 파일(파서 폭탄)을 올리는 사람, 남의 워크스페이스 id를 아는 사람, 남의
이메일을 아는 사람, 그리고 예제 토큰을 그대로 붙여 넣는 식의 운영 실수. 네트워크 수준의 대규모 DDoS와 Render
플랫폼 자체의 침해는 범위 밖이다.

| 위협 | 통제 |
|---|---|
| 남의 검진 결과 열람 | 접근 키(256비트 무작위, SHA-256 해시만 저장)가 없으면 404. 워크스페이스 id는 권한에 쓰지 않음 |
| 관리 기능 탈취 | Bearer 토큰(시간 일정 비교), 틀린 토큰은 401, 잘못된 토큰 표로는 서버가 뜨지 않음. 문서의 토큰 예시는 일부러 쓸 수 없는 자리표시(`<…>`)만 둔다 |
| 한 사람이 서버를 독점(CPU·메모리) | 방문자 진단 동시 1개(`JETTAE_MAX_CONCURRENT_SCANS`) — 넘치면 줄 세우지 않고 바로 503 + `Retry-After`. 업로드 2 MB(`JETTAE_MAX_UPLOAD_MB`), 변환한 텍스트 50,000자(`JETTAE_MAX_DOCUMENT_CHARS` — 파일 하나와 검진 한 번의 합계 모두; 진단 시간이 글자 수보다 빠르게 늘어 데스크톱에서도 41,000자 약 3초), 무료 검진의 명부·당직표·카탈로그 각 1,000행, 무료 검진 시도 접속 주소당 1분 10회 |
| 예제 재진단으로 CPU·DB 소모 | 예제는 서버 시작 때 한 번 진단하고, 방문자에게는 저장된 보고서를 돌려줌(다시 진단하지 않음) |
| 파서 폭탄 | YAML: 별칭을 펼친 항목 20,000개·깊이 50(자기 참조 별칭 거절) · DOCX: 압축 해제 합계 50 MB·항목당 30 MB·1 MB 넘는 파일의 압축률 100배 · PDF: 200쪽·2,000,000자·스트림당 2 MiB·쪽 내용 합계 8 MiB·그리기 연산 2,000,000개 · HTML: 열린 요소 깊이 512·태그 100,000개. 모두 읽는 단계에서 한국어 오류로 거절 |
| 하루 검진 한도 소진·DB 채우기 | 사이트 전체 하루 50회(`JETTAE_DAILY_FREE_SCAN_LIMIT`, 한국 시간 기준 — 7일 보관이므로 DB에는 많아야 350건) + 접속 주소당 하루 5회(`JETTAE_FREE_SCANS_PER_CLIENT_PER_DAY`). 무료 검진은 결과만 남기고 7일 뒤 삭제, 실패한 검진은 바로 삭제 |
| 이벤트·신청 도배(지표 위조, DB 채우기) | 접속 주소당 이벤트 1분 60회(`JETTAE_EVENTS_PER_CLIENT_PER_MINUTE`), 신청 1시간 10회(`JETTAE_SIGNUPS_PER_CLIENT_PER_HOUR`), 그리고 주소와 상관없이 사이트 전체 이벤트 하루 20,000건(`JETTAE_EVENTS_PER_DAY`). 이벤트는 허용 목록의 이름·값만 받아 한 줄이 수백 바이트 이하. `runbook_upload`는 서버만 기록 |
| 접속 주소 위조로 주소별 한도 회피 | `JETTAE_CLIENT_IP_SOURCE`로 앞단 프록시가 넣는 헤더(`header:CF-Connecting-IP`)나 `X-Forwarded-For`의 오른쪽 자리(`xff:<n>`)를 읽고, 방문자가 쓴 맨 왼쪽 값(`peer`)은 쓰지 않음. 배포 직후 `GET /api/v1/admin/request-info`와 꾸민 헤더로 확인(위 「방문자 주소」) |
| 남의 신청 덮어쓰기·동의 조작 | 같은 이메일의 재신청은 기존 기록을 바꾸지 않음 |
| 개인정보 과다 보관 | 원문 비저장·마스킹, 무료 검진 7일·사전 신청 1년 뒤 서버가 스스로 삭제(공개 모드에서만 — 시작할 때와 6시간마다 도는 정리 작업, 실패해도 서버는 계속 돌고 다음 차례에 다시 시도. 개발·설치형 DB는 지우지 않음), 철회 요청은 `DELETE /api/v1/signups/{email}`로 즉시 삭제(감사 로그에는 이메일 대신 짧은 해시) |
| 로그로 새는 개인정보 | uvicorn 접속 로그를 끄고(방문자 IP·쿼리 문자열이 남으므로) 앱의 요청 로그는 메서드·경로(쿼리 제외)·라우트·상태·처리 시간만 남긴다. 경로 속 이메일(삭제 요청의 `/signups/{email}`)은 가려서 기록한다. SQLAlchemy 엔진은 `hide_parameters=True`이고, DB 오류는 예외 클래스 이름만 기록(신청 행·SQL·트레이스백 없음). 토큰·접근 키·접속 주소는 기록하지 않음 |
| DB 직접 접속 | `render.yaml`의 `ipAllowList: []`로 인터넷에서의 외부 접속을 모두 차단(같은 리전 서비스의 내부 접속만 허용). 접속 문자열은 Blueprint가 넣어 주고 저장소에 없음 |
| 공급망 | 파이썬 패키지는 `constraints.txt`로 직접·간접 의존성을 모두 `==` 고정, 웹은 커밋된 lockfile로 `npm ci`. 공개 이미지에는 AI SDK(anthropic·openai)를 넣지 않고, 컨테이너는 root가 아닌 사용자로 실행 |
| 전송 구간 | Render 앞단이 HTTPS를 끝내고, 앱은 `X-Forwarded-Proto`(`FORWARDED_ALLOW_IPS`)로 https를 알아봐 HSTS를 붙인다 |
| 국외 이전 미고지 | `/privacy` 개인정보 처리방침: 운영자·문의처, 항목·목적·보유 기간, 처리 위탁·국외 이전(Render Services, Inc.(미국)의 싱가포르 서버), 권리 행사 방법, LLM 미사용. 사전 신청 동의문과 랜딩·무료 검진 화면에서 연결 |

**남는 위험(알고 운영할 것)**

- 방문자 주소가 어느 헤더에 실려 오는지는 Render 앞단 구성에 달려 있고 Render가 문서로 보장하지 않는다. 배포 직후
  확인을 건너뛰거나 앞단이 바뀌면, 주소별 한도가 꾸민 헤더로 뚫리거나 모든 방문자를 한 사람처럼 셀 수 있다. 그래서
  주소별 한도는 단순 반복을 막는 장치로 보고, 주소와 상관없는 사이트 전체 하루 한도·이벤트 하루 상한·동시 진단
  수·크기 한도·보관 기간을 마지막 방어선으로 둔다.
- 횟수 한도와 하루 한도는 프로세스 메모리에 있어 재시작하면 초기화되고, 서버를 여러 대로 늘리면 대수만큼 늘어난다.
- 화면 이벤트는 브라우저가 보내므로 스크립트로 부풀릴 수 있다(빈도 제한과 하루 상한으로 속도와 양만 묶음). 의사결정은
  서버가 직접 세는 사전 신청 수와 `runbook_upload`를 기준으로 한다.
- 무료 검진 결과에는 명부의 이름·직급·팀이 그대로 남는다(진단에 필요). 7일 보관과 접근 키로만 묶는다.
- 관리자 토큰을 가진 사람은 모든 무료 검진 결과와 명단을 볼 수 있다. 토큰은 운영자 한 명만 갖고, 새면 즉시 바꾼다.
- 무료 DB는 만든 날로부터 30일 뒤 만료되고 백업이 없다. 운영자가 내려받은 명단 사본에도 같은 보관 기간을 지킨다.
- Render 플랫폼이 앱 밖에서 따로 남기는 요청 기록·지표는 이 앱의 로그 설정으로 정할 수 없다.

## 프롬프트 인젝션
ADR-0004 참고. 판정 경로에서 LLM 호출은 0회이고, 자기 안전 시험 30건을 배포마다 실행한다.
